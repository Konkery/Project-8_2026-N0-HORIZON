## 5. КРАТКИЕ КОММЕНТАРИИ ПО ПУНКТАМ РЕЕСТРА

- **Журнал (п. 3.1)** — append-only: записи хронологически вниз, прошлые опечатки
  не правятся; единственный документ, где допускается упоминание лиц диалога.
- **PDF-конвейер (п. 3.2)** — перед регенерацией закрывать PDF в просмотрщике
  (блокировка файла); в git PDF коммитится после заморозки md-версии.
- **Реестр файлов (п. 3.3)** — temp-агрегат, пересобирается сканированием;
  актуальность среза проверять перед использованием.
- **Этап 4 (п. 2)** — по N1/N2 подписант стороны исполнителя подтверждён,
  N3 приостановлен по У.1/У.2; одновременное подписание — условие Решения №2.
- **Этап 5 (п. 2)** — реквизиты стороны заказчика из подписанной v02 (к/с 19 зн.,
  БИК 8 зн.) **сверять перед применением** в платёжных документах.
- **Каталоги ИРП (п. 3.6)** — в рамке не заполнены намеренно: ИД, ТЗ и
  план-графики живут в заказах.

## 6. ПОРЯДОК ВЕДЕНИЯ

1. Завершение этапа — статус строки п. 2 с датой и ссылкой на результат.
2. Любая новая задача, изменяющая файлы раздела, сопровождается записью в журнале
   (промт + запись) и предложением строки в этот реестр.
3. Срез `temp\project-inventory.md` пересобирается при крупном изменении структуры.
4. Временные и служебные файлы (`temp\`) в осмысленную документацию не выносятся.
